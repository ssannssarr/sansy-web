---

### <div align="center">Thank you for contributing to Sansy Web.</div>

This project is experimental and built mainly for learning, exploring ideas, and creating a music experience that feels smooth and alive. The codebase is not perfect, and it does not try to be a corporate-style project.

You do not need to over-engineer things here.

**The main goal is:**
<i>
- keep features working
- keep the app lightweight
- keep the UI feeling good
- do not remove the soul and personality of the app
</i>

---

# Before You Start:

Before working on something:

1. Check existing [issues](https://github.com/ssannssarr/sansy-web/issues).
2. Comment on the issue you want to work on(to avoid double working on same issues).
3. Fork the repository.
4. Create a new branch.
5. Keep changes focused.

---

# Setup:

Clone the repo:

```bash 
git clone https://github.com/YOUR_USERNAME/sansy-web.git
cd sansy-web
````

Create virtual environment:

```bash 
python -m venv venv
```

Activate it:

```bash 
# Linux / Termux
source venv/bin/activate

# Windows
venv\Scripts\activate
```

Install dependencies:

```bash 
pip install -r requirements.txt
```

Run the app:

```bash 
python app/app.py
```

Open:

```http
http://localhost:8765
```

# Contribution Style:

**A few simple rules:**

* Keep things minimal
* Avoid unnecessary dependencies
* Do not completely rewrite things unless needed
* Make improvements without killing the original vibe
* Working messy code is sometimes better than overcomplicated clean code
* Refactors are welcome if they actually improve maintainability

AI-generated contributions are completely fine.

Just review what the AI changed before opening a PR.

---

# Good Areas to Contribute1:

* UI improvements
* Better mobile/desktop experience
* Queue system
* Playlist handling
* Performance improvements
* Error handling
* Refactoring large frontend sections
* Better download handling
* Documentation

---

# Pull Requests:

Before opening a pull request:

* Test your changes locally
* Explain what changed
* Add screenshots if UI changed
* Keep PRs focused on one thing
